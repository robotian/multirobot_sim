# tools/sim_ui

Moved out of the root CLAUDE.md (loads when working under this directory; the root file links here).

- **`tools/sim_ui/`** (`server.py` + `index.html`, stdlib only, no pip deps): a local web UI that just runs the same scripts/commands listed above -- Start takes a **View** (`Stream (WebRTC)` / `Headed (local window)`), written to `.env` as `SIM_MODE` (`docker/isaac-entrypoint.sh` runs `runheadless.sh` or the desktop `isaac-sim.sh`; compose passes `DISPLAY`, `XAUTHORITY` and the X11 socket to the sim, harmless when streaming; for headed the server uses its `$DISPLAY` or the first `/tmp/.X11-unix` socket and runs `scripts/x11_auth.sh` first) -- `scripts/fleet.sh scene` (Start: the sim with the scene only, the job waits for it) and `scripts/fleet.sh spawn --poses <json>` (Spawn, after writing `NUM_ROBOTS`/`ROBOT_MODEL_<i>` to `.env`; the form has model + x/y/yaw per slot, *Default poses* from the sim's `state.json`, and a top-down canvas map of the lavender rows, the robots in the scene and the form's poses -- click a robot to select it, click elsewhere to move it; the Spawn button is enabled once the sim reports the scene ready; the model list is the sim's own imported `models`), `scripts/stop_sim.sh`, `docker restart a300-isaac-sim` + `fleet_ctl.wait_scene` ("reset scene": restarting the sim container is the only reliable way to put the robots' *physical* pose back at spawn -- `docker restart <robot>` doesn't, see the arm investigation notes below; the restarted sim respawns the last applied request), `restart_ros`, and the two in-container helpers `arm_goto`/`arm_joints` (`robot/bin/`). Long actions run as background jobs whose output the page polls. "Record" on an arm move runs `arm_joints --record` alongside it and plots commanded vs. observed per joint -- the same comparison used to diagnose the `joint_2` tracking problems below. Binds 127.0.0.1 by default (`--host 0.0.0.0` exposes docker control to the LAN); POSTs require `Content-Type: application/json` so other websites can't drive it cross-site. Arm moves need `sim_robot_upstart.launch.py` running (MoveIt plan mode needs `move_group`; both modes need `moveit_sim_bridge`); the SRDF's duplicate `zero` state is de-duplicated (first wins). Each robot card also has **Cut stem** / **Stop cutting** buttons (`/api/cutstem/start|stop`): start runs `ros2 action send_goal --feedback /<ns>/cut_stem plant_cutter_msgs/action/CutStem "{start_cutting: true}"` inside the robot as a job (per-patch feedback streams into the Jobs log; it first checks the action exists, i.e. `sim_robot_upstart` is up), stop sends SIGINT to that client, which cancels the goal (the server logs "Received request to cancel goal"); a "cutting" pill shows while a client is running (detected by `pgrep` on the `ros2 action send_goal.*cut_stem` process).
